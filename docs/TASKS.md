## 3. 工作包

### W00 工程骨架与边界

**目标：**一个代码库、一个 SQLite 新库、API 服务与独立采集 worker，建立第一个真实可运行入口。

- 按 CONTRACTS 建模块目录与最小模型，显式初始化/迁移；不预建岗位、用户画像、收藏、学生通知实体。
- 交付经过实际验证的依赖安装、独立数据库初始化、启动 API/页面、手动刷新和测试命令，更新 README。
- 实现健康/版本与数据集标识；启动错误不能隐式创建或替换现有业务库。
- 建立最小 CI：静态/合同检查、必要的领域/服务回归、变更范围检查；声明工作包及允许路径。
- 范围检查与首页保持项以目标分支的可信合同为准；不能让同一修改同时改规则并给自己绕过失败。
- 尽早验证私有 Site 的打包与隔离 HTTPS 开发 API 可达性；API、SQLite 文件库、worker 在开发宿主，Site 使用受控同源代理。不能默认在 Sites Workers 启动 Python 常驻服务。
- 交付 G0 核验包；演示交互显著标记，真实初始化/GET 边界要有自验材料。G1 前必须建立真实 API/新库连接，环境缺失须写明确依赖 Issue。

**历史范围：**初始骨架的跨目录建置已交付。本轮没有 W00 机器声明或整根兜底，后续修改只按本轮精确包登记；不因保留本节而取得 backend/frontend 或部署配置的全局权限。

**验收：**独立新库可初始化并重启读取；读 API 不自动建表/迁移；错误数据库配置明确失败；CI 能识别工作包范围外的修改。记录分支保护实际是否可用，不把文档规则称作平台强制权限。

### W01 华工、广工真实基础发现

**目标：**用实际官方公开来源打通列表→证据→基础字段→保存。

- 核验种子页面归属、栏目和分页；明确公告/线下活动/线上招聘分类。
- 每页基础记录即时提交；列表已有日期、时段、会场必须立即提取，不等待详情成功。
- 保存原始依据及字段状态，详情先补时间、举办地点、工作地；复杂名单/岗位不作为基础入库条件。
- 同源稳定 ID/URL 去重、内容变化、改期及仅截止日期变化均有历史记录。
- 失败保留已提交记录和已知字段；分页预算耗尽记录断点与未完成范围。

**允许路径：**原基础交付对应 W01-R3 精确登记；本轮字段/材料/队列修正归 CORE-M2，当前两校来源样本归 M1-SOURCES。不以本节概述扩大 source/domain/services/storage 范围；共享模型变动列明迁移及影响。

旧 R3/W01 登记仍仅说明历史两校基础范围，不支持 #31 新号或八校扩展。新来源使用冻结 CORE 接口；字段/相关性以本公告岗位/专业依据为准，场地与工作地分离，普通失败保留可靠旧值，旧 known 误判通过 `semantic_revision.py` 只读审计/预览后定向修订。材料错属在事务内原子拒绝，附加材料隔离不拖垮可靠核心读取。

**验收：**A01—A05、A08；实际抓取/样本范围与数据集标识有记录。不能拿复制的旧数据库或仅 fixture 宣称两校真实链路已通。

### W02 首页、搜索与简要详情

**目标：**用户能选择学校、找到机会、看清关键信息并打开正确原文。

- 固定页面骨架、卡片组件和局部样式。卡片为识别头＋时间/适用会场/工作地/原文，标题可进入简要详情。
- 简要详情只展示本公告已取得的信息、名单/岗位文本与附件，不建立独立岗位实体、查询或全国企业链接补齐链路。
- 学校、校区、类型、关键词、日期、最近/临近/历史、默认电气/全部招聘筛选按合同实现。
- 明确无关只在全部招聘入口；相关性未知保留，不能以标题缺关键词认定无关。
- 表单草稿与已应用查询分开，分页保持同一条件/数据集；旧响应不能覆盖新查询。
- 单次列表返回卡片全字段，禁止每张卡片再请求详情取工作地。来源页展示简明状态，技术细节留维护页。

**允许路径：**原基础交付对应 W02-R4 精确登记；本轮 #29/#30 使用 M1-UI 的 cards/home/detail/shared/store/client、局部样式与限定测试。全局设计变量和首页骨架保持既定范围，共享 API/代理联动由整合者按登记路径窄修。

固定 `as_of` 与 dataset 分页、草稿与已提交条件、晚响应隔离继续有效。列表成功后恢复自身操作，目录/摘要分别表示新鲜度并有界协调；不同项目/构建/data_mode 仍报警，不将新列表持续标旧。访客 DOM 与键盘可达内容不输出定位器、材料 ID/hash，后台证据与安全校验保留；技术资料只进鉴权维护页。

**验收：**A02—A04、A06、A07、A09、A10、A12；桌面和390px视口可用，真实原文跳转核验，已取得数据能逐项追到卡片。

### W03 固定十校扩展

**目标：**完成十校来源登记、适配和真实状态报告，不靠删校/换校满足计数。

- 核验每校公开主栏目、分页和校区来源；华电北京/保定属于同一学校。
- 共享网络和解析基础工具，各校选择器/特例留在适配器中；不为一校改全局页面或其他学校字段规则。
- 对正常公开来源按配置窗口持续采集；受限、未核验、失败、部分完成、真实无记录分别说明。
- 缺岗位、名单或非关键条件不阻止有效公告可见；不追求完整双选企业名单抽取。
- 独立记录官方观察范围、已发现、已入库、API/页面可达与缺失原因。取得完整分母前不报告完整覆盖率。

**允许路径：**W03 登记的十校适配器、registry 注册点、`config/schools.json`、各校脱敏 fixtures 和限定测试；其他八校文件名已在本轮表固定。统一 policy、公共写入/查询/schema/API 由共享 owner 处理，来源包不自行扩展；首页、全局样式与其他页面不属于本包。

**验收：**十校目录固定；逐校记录真实入口/栏目/归属、校区、列表解析和已观测范围，分别给自动发现、详情补全、官方材料补录能力及限制。至少三所固定学校各提供一条当前且有本公告电气岗位/专业依据的真实样本，材料→库→API→Site 可定位。受限/未检查不写零招聘，HTTP200 解析失败不刷新成功时间；受限校不计自动覆盖完成。

### W04 维护网页与真实更新摘要

**目标：**维护者可不依赖一轮代码开发来补官方材料、纠错和查看来源问题。

- 维护页有真实的服务端访问控制，学生访客保持匿名只读；不建立学生注册系统。
- 支持官方链接与合法取得的公开正文/附件，取得不了内容时要求材料证据，不能仅凭链接虚构字段。
- 预览解析结果和证据→显式提交→同一写入口保存→记录操作→可撤回；并发/重复提交不多次创建机会。
- 自动更新与人工更正发生冲突时保留依据，不能悄悄覆盖；撤回不得删除后来合法更新的内容。
- 更新摘要区分新增机会、业务更正、改期/取消、解析改进、人工更正和无变化核验；未检查与零新增不同。
- 管理页以处理来源/字段问题为核心，技术错误码不进入访客卡片。站内摘要不扩成学生推送系统。
- 在 Site 同源代理下实际验证维护登录、业务 Cookie、CSRF/Origin、预览输入绑定及真实保存/撤回；平台登录和代理服务令牌不能代替维护者授权。

**允许路径：**按 W04-A/W04-B 的已登记文件分开实施，认证/维护与摘要/待办各有固定模块；公共 writer/API/迁移/代理/路由由共享 owner 串行整合。访客首页只连接既定摘要和既定字段，不更改整体布局；本节不授予 services/storage/tests 整目录权限。

**验收：**A04、A05、A11及 M2-04—08：Site 登录与独立业务会话分别验证，退出业务会话后写入和受保护操作/待办读取均拒绝；无 CSRF、跨 Origin、过期/撤销会话、非法方法/路由均拒绝。预览不写访客事实，绑定 session/input hash/target/type/version/expiry；相同已提交请求在预览过期后仍返原回执，其他输入/版本冲突须重新预览。受限 URL 不触发越权请求。撤回只撤指定贡献，验证更正→自动更新→撤回、重复导入→撤回及后来另一人工更正；可靠未来事实与审计不删除。

摘要专项：按 Asia/Shanghai 实际提交日、每分类去重机会数对账；分类重叠明示不可相加，人工更正/撤回在无 run 日仍可见，来源保持未检查，未知不填零。官方变化、解析改进、有效无变化核验分开，HTTP200 列表解析失败不刷新成功时间；重复操作/失败不复制业务数或维护待办。自然调度和完整运营恢复仍在 W05/M3。

### W05 自动运行、备份与只读 MCP

**目标：**没有用户浏览器或 Codex 会话时，站点也能保持周期检查并暴露真实维护状态。

- 起始调度为每6小时一次，健康公开主来源24小时内检查目标；48小时陈旧提示。时间预算、公平续跑、有限重试、失败分源隔离可配置。
- API/worker/维护写入共用存储与服务合同，明确写锁和短事务；任务重复触发不会并行破坏数据。
- 定时器启动、进程退出、业务结果、来源完整性分别记录，不用健康接口替代业务验收。
- 定时采集与备份恢复在真实隔离开发宿主执行，Site 提供相应可读状态；不能把手动刷新或演示计时器当作自然调度。
- 备份保留规则、容量上限、隔离恢复演练与重启恢复有实际证据，保留唯一有效备份。
- 只读 MCP 查询版本、目录、机会、来源/刷新状态、有限脱敏诊断；按新接口适配，不复制另一套采集逻辑。
- 诊断返回明确项目身份、代码版本和数据集，不能让仍连接旧站的工具结果冒充 v2 验收。

**允许路径：**`ops/`、刷新用例/任务状态及必要API、相关配置、`tests/`。不包含域名、防火墙、全局代理、其他项目或把只读MCP改成服务器写工具。

## 5. 工作纪律和交付记录

- 技术路径固定在 CONTRACTS，日常命名、局部超时/预算等自行落实并记录；不逐项向负责人确认。
- 自行做出的技术假设不得改变八项已确认选择。需要改变产品范围时列明影响，不以“顺便优化”扩大任务。
- 每个工作包交付目标、修改范围、验证、未完成项与后续依赖，更新 STATUS 一处。
- 不用源代码行数、测试总数、仓库存量或下拉选项数代替实际功能完成。
- 只有当前实现已具有实际命令时才写“运行某命令”；未实现命令是交付要求，不能伪装为可运行入口。
- 访问条件只阻塞依赖该环境的动作，来源限制只阻塞该源，运营天数不足只阻塞运营结论。
- Site 所需隔离开发 API 若不可用，真实链路验收也受阻，不能说只影响生产。G0—G4 按顺序交付清单；每个用户失败/阻塞项查重补 Issue、限域修复、同编号复验。未收到用户反馈不关闭实现/反馈/Gate Issue。
