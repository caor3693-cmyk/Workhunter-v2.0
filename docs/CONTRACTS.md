# Workhunter v2.0：数据、接口与模块契约

版本：v1.3；日期：2026-10-11。本次冻结 M1 修复与 M2 来源、材料适用、统一写入、schema3 迁移、维护会话和真实摘要合同，产品范围不变。产品范围以 [PRODUCT.md](PRODUCT.md) 为准，工作包见 [TASKS.md](TASKS.md)，阶段排期和手工核验见 [ROADMAP.md](ROADMAP.md)、[MANUAL_QA.md](MANUAL_QA.md)。
本文件定义待实现的行为，不表示新仓库、服务、采集、旧工程归档或上线已经完成；实际状态只记录在 [STATUS.md](STATUS.md)。

## 1. 已确认范围

- 首版围绕十校公告/活动发现；不建设独立岗位库、岗位筛选、全国企业直采或完整名单采集工程。
- 提供简要详情，展示本公告已经取得的核心事实、名单片段、岗位文本及附件；不要求完整复刻原文。
- 标题可进入简要详情；卡片正文只含时间、举办地点、工作地点和一个原文链接，不加名单、岗位计数或额外按钮。
- 默认电气相关列表保留相关性未知的机会；已核实无关项只在“全部招聘”入口展示。
- 十校保留，受限校标状态、支持官方材料补录；其他学校可按实际完成范围上线，不冒称十校自动覆盖完成。
- 提供受保护的维护网页；不建设学生账号、收藏同步、订阅推送、待遇比较或自动投递。
- 使用新业务库，从近期官方来源重新采集；旧业务库和原文只读留存，不将旧推断或关联直接导入。

## 2. 最小数据对象

| 对象 | 必需内容与边界 |
| --- | --- |
| School / Campus | 稳定 `school_key`、名称、可选校区与归属证据；校区 ID 从目录取得，不在前端硬编码 |
| Source | `source_key`、所属学校、栏目、官方入口、适配器、采集范围；配置与运行状态分开 |
| Opportunity | 内部 ID、学校/来源身份、原标题、类型、核心事实、相关性、业务状态及系统时间 |
| SourceMaterial | 稳定材料及版本、来源 URL、官方记录 ID、材料 hash、获取时间、原始材料引用、获取/解析状态；不由某公告后到达而改写已有材料归属 |
| OpportunityMaterial | 公告与材料的适用关联：公告身份、材料版本、关系种类、locator/scope、依据和附件取得链；一份共享列表可有多个独立可核验关联 |
| ProcessingTask / Run | 列表/详情任务、游标、预算、尝试次数、结果、提交情况；中断后可续跑 |
| Change / ManualOperation | 变更字段、前后值、来源、操作者或运行 ID、原子提交时间；人工操作可预览及撤回 |

学校种子来自 `config/schools.json`；入口是待核验种子，不代表已验证可抓取。华电不同校区属于同一学校。
固定学校 key 为 `scut / gdut / ncepu / shiep / neepu / csust / ctgu / gzhu / hnu / csu`。来源政策集中在 `backend/domain/source_policy.py`，来源注册集中在 `backend/sources/registry.py`，由同一 `config/schools.json` 表达学校、来源、栏目、官方入口/获准域名、第三方托管的学校租户依据、校区映射及能力状态。domain、transport、adapter、人工材料输入复用同一准入事实，各边界仍独立验证安全 URL、解析地址、重定向、大小和类型；不得各写两校域名特例或为扩第三校放宽准入。能力状态与本轮观察结果分开，不用目录登记、HTTP200 或一个成功详情冒充列表已解析/全校覆盖。
首版类型固定为 `campus_talk`、`job_fair`（含双选会）、`online_recruitment`、`announcement`；保留来源原始类型文本。
详情中的企业名、岗位文本作为本条机会的有限证据片段保存，不创建全局 Company / Job / EventJob 等未来实体。
校区仅在官方信息足以确认时填写；学校所在地、孤立楼名和相似地址不能代替校区归属证据。
同源身份采用 `source_key + 官方记录ID`，无官方 ID 时采用规范化稳定 URL；变更日期/标题不得改变身份。
跨源相似项只形成候选；未经本场次、主体和届次等证据确认不得合并，补充材料仍保留各自来源身份。

## 3. 字段与证据状态

| 字段 | 唯一含义 |
| --- | --- |
| `published_date` | 官方发布日期；不得用首次收录日、届次或举办日回填 |
| `event_date / start_time / end_time` | 本场举办日期及时间；日期精度不足时不补 `00:00` |
| `deadline` | 明确适用于本条招聘的投递截止；不从活动结束推断 |
| `event_venue` | 本场学校/校区/楼宇/教室，或有证据的“线上” |
| `work_locations` | 本公告明确披露的工作地列表，可直接从公告提取，不依赖岗位实体 |
| `first_seen_at` | 本系统首次收录时间 |
| `last_attempt_at / last_success_at` | 来源最近访问尝试 / 最近成功取得可用材料的时间，失败只更新前者 |
| 字段 `observed_at` | 该字段证据实际取得并核对的时间；失败或只重见 URL 不刷新旧值时间 |
| `content_changed_at` | 系统检测并提交业务内容变化的时间 |
| `source_updated_at` | 官方明确披露的修改时间；没有证据就为空，不使用系统时间代替 |

日期使用 `YYYY-MM-DD`，时刻使用 `HH:mm[:ss]`；系统时间戳带明确时区，页面统一显示 Asia/Shanghai。
对日期、时刻、举办地点、工作地点等关键事实维护有限的 `field_observations`，不构建任意字段工作流框架。

| `state` | 成立条件 | 访客文案 |
| --- | --- | --- |
| `known` | 原文明确且适用于本条记录，有定位证据 | 显示真实值 |
| `not_collected` | 必要列表/正文/附件尚未取得 | 暂未取得 |
| `pending_extraction` | 材料已取得，字段尚待处理 | 待核实 |
| `parse_failed` | 材料已取得，解析不能可靠确认 | 待核实 |
| `not_disclosed` | 已检查适用材料，确实没有该信息 | 原文未披露 |
| `not_applicable` | 该记录没有对应语义，如普通公告无宣讲会场 | 省略对应行 |
| `conflict` | 多项有效证据冲突，尚未裁定 | 待核实 |

每项证据含 `material_id`、`source_url`、对应片段/定位、适用范围、`observed_at`、`parser_version`；数组字段可关联多份证据。
材料获取另记 `pending / success / failed / restricted`；获取失败不能变成字段“未披露”。
只有部分正文、未知附件或不完整名单时，不能对其未覆盖内容宣称未披露或完整。
可靠旧值遇到失败仍保留；保存本轮失败状态而不清值、不刷新该值核验时间。缺失字段不等于官方撤回。
相关性只由本公告适用的招聘岗位/专业依据判定；公司行业、服务对象或简介中的电网/自动化关键词不证明岗位相关。材料不足为 `unknown`，保留在默认电气列表；只有充分、明确的本次岗位/专业依据才能判 `unrelated`。标签与值分段、表格等可核验内容应支持提取；已见线索但无法可靠解析记 `parse_failed` 或待核实，不能写为 `not_disclosed`。
发布时间和举办日期分别拥有证据状态；其中一个已知不能消除另一个字段的缺失原因。
岗位文本中的地点只在明确适用于本场时汇总；公司名、总部、注册地址、学校/会场城市不能充当工作地点。
“招聘地点”“招聘城市”等招募/举办标签不得直接当作工作地；必须有本公告任职地点/工作地点的明确依据，不能将已复现的学校就业大厅误判为工作地点。
多企业活动使用“已披露工作地点”，并标识证据范围；不能暗示每家企业都在汇总地点招聘。
人工更正与后续自动观察冲突时保留两份证据并进入维护待办，不能静默覆盖已确认更正。
普通失败/未知观察保留可靠旧值，与纠正已证实旧误判是两个通道。`backend/services/semantic_revision.py` 先对真实旧记录只读审计，输出逐记录旧值、建议新值/状态、适用证据、原因、目标版本、影响与回退方式；明确复核后只在独立候选库通过统一 writer 定向修订。修订允许以明确证据将旧 `known / related` 改为正确值或 `unknown`，保留原观察与修订历史；禁止全库直接 UPDATE、清空所有 related 或把普通失败当作清值理由。未经真实逐项核验不宣称影响条数。
“新增/修改”记入变更日志；“未来活动/活动已结束/官方取消/明确招聘截止”分别判断，不能混为一个 `status`。
截止未知只能表达未确认截止，不显示“确认在招”；官方取消活动也不自动关闭其他招聘内容。

## 4. 完整卡片投影与简要详情

列表 API 一次返回卡片所需全部字段，页面不得逐卡片请求详情或抓原文来补必填展示。
每项必有 ID、原标题、学校/校区、类型、`date_basis`、日期/时段、举办地点、工作地、业务状态、原文 URL 和详情路径；未知值为 null/空数组并附对应状态，不省略契约字段。
`date_basis=event / publication` 表明采用举办还是发布日期，由官方材料语义决定，不能因为日期缺失而临时切换。
卡片识别头为原标题、学校及类型；标题链接指向站内简要详情，原文链接指向本条可核验官方页面。

| 正文项 | 展示规则 |
| --- | --- |
| 时间 | 活动展示举办日期/时段；普通公告展示“公告发布时间”；取消/改期信息合并在时间行 |
| 举办地点 | 按原文精度展示；明确线上显示“线上”；普通公告无此语义时省略 |
| 工作地点 | 展示有据值；多企业活动用“已披露工作地点”；无值按第 3 节状态表达 |
| 原文 | 一个真实可点击的 HTTP(S) 链接；禁用 `javascript:`、凭据 URL 等非公开阅读目标 |

不在卡片加入薪资、名单、详情折叠、岗位数量、抓取时间、系统 ID、解析警告或维护按钮。
工作地点列表保留完整已取得值；默认卡片最多显示 5 项，其余写“等，详见原文”。展示截断与来源覆盖不全分别标识。
简要详情包含：核心事实、对应官方来源、已取得名单片段、已取得岗位文本、适用附件及必要的字段解释。
名单只表达本材料明确提及的参与企业；岗位片段只表达本公告已有内容，不产生独立岗位 ID、搜索或推荐。
详情标明片段范围 `partial / complete_for_material / unknown`；“本材料完整”不等于整场活动完整或全校覆盖完整。
附件和补充来源链接仅在详情显示；只保留已核验适用链接，不为了详情完整启动全量企业/名单追查。
未知详情仍可打开并看到已取得事实及原文；空名单不是“没有企业参加”，空岗位片段不是“没有岗位招聘”。
API 只提供结构化文本及安全链接；页面使用文本渲染，不直接执行或插入未经处理的来源 HTML。
访客 DOM、键盘可达内容和公开页面不输出 locator、材料 ID/hash、解析器版本或原始诊断；不能仅以 CSS 隐藏。保留原文、适用附件、范围和 unknown/conflict 的必要中文解释；工程证据只在业务鉴权后的维护资料中展示。

### schema3 材料适用与读取边界

`SourceMaterial` 的稳定身份/内容版本与公告适用关系分离；适用关系必须含 `opportunity_id`、公告的 `school_key / source_key / 官方记录ID或稳定URL`、`material_id`、关系种类（列表、正文、附件等）、`locator / scope` 和核验依据。共享列表材料须为每条公告提供各自定位；同校、同域、同名企业或 hash 相同不足以证明适用。附件必须来自该公告适用正文/列表中取得的链接链，保留父材料、原链接和实际公开目标，全部经过统一来源政策校验；不得把另一公告附件当作本公告补全。

writer 在事务内校验材料身份、适用关系及字段/片段/附件引用；每个字段证据必须引用与本条公告稳定身份匹配的适用关联，不能从同来源另一条关系借证据。错属或缺失关联原子拒绝，不留下部分记录、错误历史、提交回执或 dataset 更新。重复入库不会重复关系，也不会因 B 后到达改坏 A。详情查询只投影经核验适用的材料及其字段，不能仅因同来源或 `opportunity_id=NULL` 放行。

迁移/显式写入将可疑旧附加关系隔离并生成去重维护待办，保留原材料与审计。可选附件、名单或片段损坏不得使已可靠取得的核心详情整体 503；省略不可信附加内容并给出必要的待核实说明。核心字段也必须有可信依据，不因“保留 core”绕过校验；数据库结构损坏仍按数据库不可用处理。GET 不写隔离状态、不建待办、不迁移；持久隔离只能经显式迁移或统一写入口执行。

以下是合成字段示意，不是真实采集或覆盖证据；`field_observations` 按第 3 节逐项提供。

```json

  "id":42,"school_key":"scut","school_name":"华南理工大学","campus_id":null,
  "title":"示例校园招聘公告","kind":"announcement","date_basis":"publication","source_url":"https://example.org/notice/42",
  "published_date":"2026-10-10","event_date":null,"start_time":null,"end_time":null,
  "event_venue":null,"work_locations":["广州","深圳"],"work_locations_scope":"this_announcement",
  "relevance":"unknown","event_status":"not_applicable","recruitment_status":"unknown",
  "field_observations":{"event_venue":{"state":"not_applicable"}},
  "detail_url":"/opportunities/42"

```

## 5. 公开 API、筛选与分页

| 接口 | 契约 |
| --- | --- |
| `GET /api/catalog` | 十校、校区、来源可用性及零数据状态；学校不会因失败/零条目被移除 |
| `GET /api/opportunities` | 完整卡片投影、`dataset_id`、`applied_filters`、`total`、`offset`、`limit`、`has_more` |
| `GET /api/opportunities/{id}` | 第 4 节简要详情，不请求外站；不存在返回 404 |
| `GET /api/updates/summary` | 今日新收录/修改及最近检查摘要；重解析、人工更正与官方变化分开计数 |
| `GET /api/sources/status` | 学校来源的简明状态/最近成功时间，不公开内部路径、原始日志或凭据 |
| `GET /health`、`GET /version` | 数据库可用性、明确构建标识和数据集标识；不等同业务覆盖验收 |

机会列表参数：`school_key`、`campus_id`、`campus_unknown`、`kind`、`keyword`、`date_from`、`date_to`、`view`、`scope`、分页参数。
`scope=electrical` 为默认：包括 `related / unknown`；`scope=all` 另外包括有证据的 `unrelated`。不得只凭标题无“电气”判无关。
`view=recent / upcoming / history / undated`；`undated` 返回业务日期未知项，入口始终可达并保持学校等条件。
业务日期：`date_basis=event` 采用 `event_date`，`publication` 采用 `published_date`；普通公告及无活动安排的学校线上招聘使用后者。
原文明示有活动安排但尚未取到日期时仍是 event，不能借发布日期冒充举办日期；日期过滤不得用收录时间代替。
`upcoming` 仅未来/当天且未取消活动；`history` 为已过活动及近期窗口以前的公告；未知项不混入明确日期命中。
起始近期窗口取并集：任一机会的 `published_date` 在近 30 天内，或其 `event_date` 在当天至未来 30 天内；可在配置中调整，API 返回实际应用窗口，不宣称已采集完整。近期与历史视图允许重叠，例如刚发布但已结束的活动；首次收录时间只可补排序，不能补筛选日期。
近期列表按官方发布日期降序，缺发布日期时用首次收录时间排序并在详情说明；临近活动按举办日期/时刻升序。
同排序值使用内部 ID 作稳定次级键；默认每页 20，允许 1—100；核心筛选、计数和分页在 SQL 中完成。
不存在的学校/记录返回 404；非法值、学校校区冲突、具体校区与 `campus_unknown=true` 同用返回 422。
未提供条件即无该项限制；不支持的参数明确返回 422，不能隐式恢复岗位、待遇或严格/宽松筛选。
数据库不可读返回 503 与可理解提示；来源抓取失败不使已有列表整体变成 503。

服务实现后可执行的只读请求示例（不是本轮已运行结果）：

```bash
curl -sS 'http://127.0.0.1:8000/api/opportunities?school_key=scut&view=recent&scope=electrical&offset=0&limit=20'
curl -sS 'http://127.0.0.1:8000/api/opportunities/42'
```

首次查询返回当前 `dataset_id` 与 `as_of`（Asia/Shanghai 的查询日期）。追加分页必须携带同一 `dataset_id` 和 `as_of`；窗口、临近/历史判断及相应状态均沿用该日期，不能跨午夜暗中移动。缺任一参数返回 422；数据集变化返回 409 `dataset_changed`，不返回可供拼接的新页。`as_of` 仅用于冻结阅读窗口，不是来源核验时间；非法或未来日期返回 422。重新查询第一页默认取得当前日期。
同一次响应的行、计数、字段和 `dataset_id` 在一致读事务中取得；机会公开投影变化后才在提交时更新对应数据集标识。仅巡检时间、来源运行状态或日志变化不触发机会列表换代。缺发布日期的排序使用首次收录完整时间戳，不截成日期；所有数字 ID/offset 有 SQLite 整数上界校验，溢出是字段明确的 422。
前端分别保存草稿条件、已提交条件、当前页及请求序号；翻页只使用已提交条件，不读取未提交表单。
新查询/学校变化终止或淘汰旧请求；失败保留旧结果时必须保留旧范围说明，不能挂上新学校标签。
收到 409 后保留当前已提交条件、清除旧分页并重载第一页；不将不同数据集结果混排。
空库、所选校暂未收录、筛选无匹配、日期未知、请求失败分别呈现；未检查不能显示“今日零新增”。
列表、目录、摘要分别记录状态与新鲜度。列表自身成功且条件/身份可信后恢复列表操作，不等待旁路请求；可信新列表与旧旁路 dataset 不同，只发起有界协调，不把新列表统一标成旧结果。项目、构建、data_mode 不匹配仍明确提示；保留 dataset/as_of 分页冲突与晚响应隔离。编辑学校/校区只改草稿，提交只发本次列表查询，重载使用已提交条件；不得为每次查询取消并重启仍有效的旁路请求。

## 6. 受保护维护页与人工操作

维护功能仅包含：贴官方链接/公开正文或附件、核对预览、补录/纠错/撤回、来源状态与失败待办。
学生访客没有写入口。维护 API 独立鉴权；浏览器不携带服务密钥，配置/密码/会话密钥不提交仓库。
使用服务端可撤销维护者会话、HTTPS 和 Secure/HttpOnly/SameSite Cookie，设置明确 Path 和过期时间；所有写请求校验 CSRF、固定允许 Origin 及来源边界，隐藏按钮不等于鉴权。口令只保存带随机 salt 的自适应 hash；会话令牌不可预测，服务端保存可撤销记录。登录失败限制及记录保留有界，返回统一失败提示，不将口令、会话/CSRF token、服务密钥写入日志或仓库。

| 接口 | 行为 |
| --- | --- |
| `GET /api/admin/session` | 返回最小业务登录状态及同源 CSRF bootstrap；匿名状态不返回受保护操作、材料或诊断 |
| `POST /api/admin/session/login` | 校验同源 CSRF/Origin、口令和有界失败策略，建立独立业务会话；Site 平台身份或代理令牌不能代替此步骤 |
| `POST /api/admin/session/logout` | 校验会话、CSRF/Origin，撤销服务端会话并清除业务 Cookie；退出后旧会话不可再读受保护资料或写入 |
| `GET /api/admin/operations` | 鉴权后有界读取操作回执/历史与必要维护证据；匿名不能取得操作资料或诊断 |
| `GET /api/admin/tasks` | 鉴权后有界读取去重维护待办；只读投影，不在 GET 创建或处理待办 |
| `POST /api/admin/materials/preview` | 接收学校/来源、URL、可选公开正文/文件与操作类型，获取/解析后返回候选事实、证据、前后差异，以及服务端生成的 `operation_id / preview_hash / base_version / expires_at` |
| `POST /api/admin/operations/commit` | 提交 `operation_id + preview_hash + base_version`，重新校验后原子写入，不接受未预览的任意 SQL/字段 |
| `POST /api/admin/operations/{id}/revert-preview` | 生成撤回差异，返回新撤回操作的 `operation_id / preview_hash / base_version / expires_at`，绑定被撤回操作 `{id}`，不改变业务事实 |
| `POST /api/admin/operations/{id}/revert` | 消费对应撤回预览的 `operation_id + preview_hash + base_version` 执行逆向更正；保留材料和审计，不删除整条历史 |

预览可以暂存有期限的受保护材料，不能提前更新机会、字段、业务历史或 dataset，也不能对访客可见。服务端绑定维护者会话、actor、目标记录/稳定新身份、操作类型、规范化输入及 input hash、材料适用、base_version、preview hash 和 expires_at；提交只能消费同一绑定的输入，不能接受客户端自报 actor、换目标/类型或跨会话挪用。预览和材料获取在事务外，正式保存再次校验并在统一 writer 原子提交。
URL 获取限于登记且归属已核验的公开来源；企业原文只有作为本公告适用材料时处理，不启动全国企业直采。
获取前后校验协议、域名、解析地址和重定向；拒绝内网/环回/凭据地址，文件有大小/类型上限，不执行上传内容。
遇登录、验证码或明确访问限制停止路径；维护者可补充合法取得的公开材料，来源 URL 本身不能代替内容证据。
已经成功提交的相同 operation_id、同一会话绑定和完全相同输入，先读取同一提交回执；即使预览随后过期或目标后来更新，仍返回该回执，不重复写入。该幂等回读仍须校验当前会话权限、CSRF/Origin 与原输入绑定。未提交预览过期、同 ID 不同输入/目标/类型或基础版本变化返回明确 409 并要求重新预览；响应丢失后的重试、双击和并发提交遵循同一规则。
人工提交记录操作者、适用范围、证据、前后值和时间；不修改无关学校/机会，不隐式恢复受限自动源。
撤回只撤销指定人工操作的贡献，保留原操作、材料、审计及新的撤回记录。字段更正恢复仍适用的前值；相关字段后来有合法更新时先生成冲突与新撤回预览，不覆盖后续事实。人工新增若不再有其他有效贡献，可撤销该人工可见贡献，不删除后来自动/人工取得的可靠事实、不解释成官方取消。重复导入/重复撤回保持幂等，不连带清空其他字段或历史。
来源获取和预览在事务外执行；业务写入与 worker 共用第 7 节唯一写入口及写锁。
维护页不提供任意服务器命令、全库 SQL、凭据查看、批量删除生产库或修改其他服务的功能。

## 7. 来源输出、调度与持久化

来源列表输出固定结构：`source_key / channel_key / records / next_cursor / scope / completeness / material_refs / warnings`。
本轮适配接口固定为 `discover(source_config, fetcher, cursor=None) -> SourcePage`；`enrich(candidate, fetcher) -> {patch, material_refs, warnings}`。候选采用 Opportunity 同名字段，校区以有官方依据的 `campus_key` 表达，材料暂用 `reference_key`，字段证据暂用 `material_ref`。统一写服务校验来源/学校/校区归属、七状态及安全 URL，解析为真实 `campus_id / material_id` 后提交；适配器不能自造数据库 ID。
关键字段为 `published_date / event_date / start_time / end_time / deadline / event_venue / work_locations`，候选均带逐项状态。已知字段必须有实际材料片段及适用范围，未知不得存伪值。名单/岗位片段含 `text / scope / evidence`，附件含 `label / url / scope / evidence`；只保留适用的公开官方链接。
传输返回实际 bytes、最终公开 URL、SHA-256、获取时间与隔离原始材料引用；失败/受限也登记材料状态和本轮警告。材料内容哈希不是机会身份。网络在事务外，统一写入口在跨进程独占锁内开始短事务；列表游标、机会、材料、字段历史及 dataset 原子提交。列表任务（opportunity_id 为空）仍有稳定唯一约束；未提交任务可重做，已提交任务不因重启重复创建。
每条记录含稳定身份、学校、原标题、类型、官方 URL，以及当前可验证字段；类型/日期含义来自来源栏目和标签证据。
详情输出为字段观察、适用附件、有限名单/岗位片段及证据；不得通过来源私有 `_flag` 控制全局入库规则。
`completeness` 必须说明本页/本栏目/指定窗口范围；只取一页、遇限流或耗尽预算只能报部分，不能报告全校完成。
来源观察分别表达 `verified_empty`（识别正确且已验证本范围完整空页）、已解析的有限范围、`parse_failed`、`restricted`、`failed` 和 `not_checked`。HTTP200/空 JS 或无法识别列表仅表示取得响应，不计列表成功、不刷新 last_success。失败/限制只记录尝试与原因，保留上次真实成功；未取得完整范围时，观察到 0 条与官方无招聘不同。
列表已披露的日期、时段、地点立即结构化和分批入库；详情失败不撤回基础机会，也不等待岗位解析。
任务优先级为基础发现→核心字段补全→已有材料片段；名单深挖或岗位结构化不得成为首版隐性前置任务。
网络请求在事务外；来源适配器不接收数据库 session，不执行 SQL，不改变全局筛选或页面。
单个定时 worker，采集与人工提交共用同一数据库写锁及 services 写入口；取得锁后再开始短事务。
写入机会、证据、变更日志、任务提交结果与数据集标识应原子完成；提交成功后才报告“数据已更新”。
所有被写入的业务字段纳入统一差异判断，包含 `deadline`；仅截止日期变化也必须更新历史、内容时间和修改统计。
进程崩溃只重做未提交任务；已有来源身份和 operation_id 保证幂等，重复调度不能启动第二个并发写入流程。
起始每 6 小时调度；健康来源 24 小时未复核产生维护待办，48 小时明显提示陈旧；配置可按实测调整。
单源/单轮有请求与时限预算、有限重试和公平续跑；明确访问受限停止对应路径，其他来源继续。
定时触发、进程退出、业务提交、采集完整性分别记录；新收录不等于官网今日发布，未检查不等于零变化。
原始材料、日志、数据库、备份存运行持久目录；源码仓库仅保留可公开配置和经处理的最少样例。
数据库采用显式迁移；GET、应用导入和健康检查不自动创建/迁移/清空业务库。旧库不得作为新库默认连接目标。

### 7.1 跨轮次公平推进与到期复核

任务身份由来源/栏目、稳定公告身份与处理阶段决定，游标按来源/栏目持续保存；run_id 只表示某次执行/尝试，不拥有或重置任务。普通新 refresh 与显式 resume 都能消费旧待补及续页；重新见到已完成记录不重置其 pending 状态或抢占详情预算。中断仅重做未提交任务；重复页去重、预算终止与失败退避保留断点，受限单校不拖住其他校。

每轮有限列表预算为头部发现与尾部续页预留可执行份额；详情按稳定等待顺序与有界轮转推进新/旧 eligible 任务，不让新头部反复挤掉旧待补，也不只续旧轮而永远漏新公告。具体权重、任务到期/退避时间及可复核周期是有界配置，必须在候选材料记录实值与可保证的轮次上限，不能用无限扫描或增加预算代替公平性。

固定反例：3 页、每页 1 条，每轮 2 列表页/1 详情预算，连续 3 个普通新轮次后，3 条详情均至少处理一次；加入 1 条新头部公告后，下一普通轮发现它，新头部与旧待补在随后最多 4 个正常轮次内均取得一次详情处理机会。异常/受限/退避任务另列原因与 next_eligible_at，不算成正常成功。验证普通刷新、resume、进程中断、重复分页、单校失败和预算终止。

committed 详情仍按有界到期策略重新核验；没有新列表证据不能永久跳过。即使列表不变，详情正文变化也须在冻结的复核周期内发现、提交并正确记账；有效无变化复核不新建机会/业务变更、不换 dataset，访问失败不刷新旧字段证据时间。

### 7.2 统一写上下文与 schema3 显式迁移

自动观察、人工补录、字段更正、语义修订及撤回共用 writer 与写上下文：可信 actor、`run_id` 或 `operation_id`（按操作来源选择其一）、目标身份/版本、材料适用关联、变更类型、原因、幂等标识和事务结果。actor 来自 worker 或已鉴权维护者/显式修订执行上下文，不能信任客户端自报身份；人工操作不伪造采集 run。官方原文观察与人工决策分别保存，冲突记录与待办复用同一判断，不在 API/worker/维护服务各写一套规则。

机会、适用关系、字段观察、变更历史、操作回执、任务提交和必要 dataset 更新一起成功或一起回退；网络和预览在事务外，获得独占写锁后只执行短事务。公共投影有实质变化才换 dataset；无变化观察、重复操作回执、鉴权状态及纯技术迁移不换机会 dataset。

目标 schema 为 3。当前实际 schema2 先留可恢复的一致备份，再在独立候选库显式执行 schema2→3；仍支持的 schema1 经同一规则到 schema3，不绕开材料校验或另写数据转换逻辑。保留机会 ID、材料及历史、data_mode 和数据身份，不删除重建、不凭空发明适用关系。迁移只能从可核实的本条身份与定位依据重建列表适用关系，legacy `opportunity_id=NULL` 不自动表示可共享；无法核实的附加关系隔离保留。纯结构迁移保留 dataset；若隔离或修订改变访客投影，作为明确的业务修订通过同一写上下文另记历史并原子更新 dataset。

备份取得一致 SQLite 状态并记录源身份、schema、材料/历史数量与可恢复位置，不用复制活动数据库文件冒充一致备份。故障注入须证明事务原子回退或由备份恢复到迁移前状态；失败时不留下半迁移数据库或丢失唯一备份。GET、health、模块导入不建表/迁移；服务发现旧 schema 只报可理解的需显式迁移状态，不自修复。迁移备份是本次数据变更前提，完整运营备份演练和自然调度仍属 M3。

### 7.3 实际提交摘要与维护待办

`backend/services/updates.py` 从已提交业务事件计算摘要，不依赖“今日是否有 run”才能看到人工操作。按 Asia/Shanghai 的实际 committed_at 日期归档，跨午夜结束的 run 不全部算到开始日。每分类按 distinct opportunity ID 计数，不把多字段/多证据条数称为招聘数；重复抓取、保存和无变化重试不增加业务数。

首次收录总集合可细分当前窗口新收录、历史补齐及日期待核实；近期与历史遵循公开时间视图，可能重叠，未知日期不冒充日期命中，总集合覆盖其他有效已知日期记录。官方业务变化（含改期/取消/截止）、解析改进、人工更正及撤回分别给出机会集合。同一机会可同时属于不同分类，接口/页面明确“分类可能重叠，不可相加”；不静默把解析改进记为官方变化。有效无变化核验另计检查情况，不作为业务变化。

当天无采集 run 但有人工更正/撤回，仍显示真实已提交人工数，同时来源为未检查；不能因此显示“今日检查零新增”。可审计的提交集合可给实际计数，自动检查/发现数量不可确定时为 null/未知，不从无 run、失败或受限推断零。HTTP200 解析失败不更新最近成功；已检查无变化、部分取得、限制/失败和未检查分开。

`backend/services/maintenance_tasks.py` 按稳定来源/原因及必要机会/字段范围去重聚合字段待补、材料隔离、自动/人工冲突和公开限制；重复失败更新同一待办的尝试/依据，不复制待办，不永久吞掉新证据。处理完成保留审计；GET 只读投影，待办持久化经统一写入口。技术原因只在受保护维护资料，访客只看简明状态；M2 不编造自然调度、下一次运行时间或连续运营天数。

## 8. 模块职责与受控改动

选型固定：Python/FastAPI、SQLite、原生 ES modules；一个代码库、一个数据库、API 与 worker 两个运行入口。

### Site 阶段验收适配

阶段验收使用 owner-private Site，承载原生前端及固定 `/api/*` 同源代理；Python/FastAPI、SQLite 文件库和定时 worker 在隔离 HTTPS 开发宿主运行。Sites 的 Workers 宿主不能直接当作现有 Python 常驻服务和文件库宿主，不为阶段验收迁移整套业务到 D1 或另一框架。

- 代理仅转发登记的方法/路径到固定上游，设置超时及大小上限，不提供任意 URL 代理，不另写采集或业务规则。适配代码集中在 `ops/preview/`，以 Sites 当前支持且实际验证的构建方式打包。
- 上游服务凭据只放 Site 服务端 secret；不放前端、URL、源码、LocalStorage 或公开变量。访客端只请求 Site 同源接口。
- 保留 Sites 平台登录；维护权限仍由业务服务校验。平台登录或上游代理令牌不单独代表维护者权限，不新增学生账号系统。
- 代理只转发必要业务 Cookie/Header，不转发 Sites 平台 Cookie。维护会话 Cookie 归 Site 同源，保留 Secure、HttpOnly、SameSite 和正确 Path，不带上游 Domain；维护写入校验会话、CSRF 与固定允许 Origin。
- G0 可以用明确标记的 fixture 验界面，但 W00 的真实初始化/读写边界仍须自验。G1 起主流程必须使用同契约真实 API 和新库，G2 维护操作必须真实入库且可撤回。
- 每次阶段包记录 Site URL/版本、前端提交、后端提交、dataset 和真实数据范围。本机 `127.0.0.1` 示例仅供本机验证，不能作为远程 Site 的 API 地址。
- 没有真实可达的开发 API 时，保持对应验收阻塞，继续独立实现；不得以旧站、静态快照或演示写入代替真实链路。全部 Gate 通过后再执行正式部署。

| 目录 | 负责与依赖边界 |
| --- | --- |
| `backend/domain/` | 字段、身份、状态、证据和合并纯规则；不依赖 HTTP、SQL、DOM |
| `backend/sources/` | 通用传输、各来源适配及材料解析；仅输出领域观察，不依赖 storage/API |
| `backend/services/` | 编排采集、补全、归并、人工操作；组合 domain/sources/storage |
| `backend/storage/` | ORM、迁移、查询、事务、材料引用；不识别学校选择器或发网络请求 |
| `backend/api/` | 校验、服务调用和有界投影；不自行复制采集/合并规则 |
| `frontend/api/`、`frontend/state/` | API 客户端、已提交查询、分页和竞态管理 |
| `frontend/pages/`、`frontend/components/`、`frontend/styles/` | 页面、局部组件及样式；不推断招聘事实 |
| `ops/`、`config/` | worker 调度、备份发布、只读诊断；官方种子与非秘密参数 |

目录按实际职责建立，不生成通用插件框架、命令总线、Redis/Celery、全站 LLM 抽取或未来 Job 空模块。
普通来源修复仅改该适配器和样例；不得顺手重排首页、改全局身份/类型或修改所有来源日期规则。
共享字段/API/迁移/首页骨架/全局样式/部署须作为显式联动工作包；CI 范围规则以可信基线核对，实施分支不能自行扩权。
只读 MCP 复用公开查询及受保护、有界诊断，不另写采集引擎、不升级为服务器写权限；日志脱敏且返回有上限。
