## 8. R4：完成 #9/#10，卡片、详情与一致查询

允许路径：`frontend/components/` 卡片/详情、`frontend/pages/` 指定入口、`frontend/state/` 查询状态、`frontend/api/`、对应局部样式；`backend/api/app.py`、`backend/services/queries.py` 对应查询及必要索引/测试。
与 R3 共享后端文件串行整合；日期窗口/分页接口新增参数按 R0 先完成有限合同补充，再实现双方，不能私自接受未知参数。

1. 列表一次返回完整卡片字段；实现标题→站内详情、原文→精确官方目标。移除非空 items 仍被 M0 提示遮蔽的分支，不逐卡片请求详情。
2. 卡片只含识别头、时间、适用会场、工作地、一个原文链接；活动时间与公告发布时间按 date_basis 显示，纯日期不补 00:00/08:00。
3. 七种字段证据状态按合同显示；普通公告没有会场语义时省略，多企业活动用“已披露工作地点”，默认最多五项且详情保留全部有据值。
4. 详情显示已取得事实、限定本公告的名单/岗位片段、适用附件及覆盖范围；详情不全仍保留核心事实/原文，不建立独立岗位实体。
5. 客户端按规范 pathname 验证固定公开路由及数字详情 ID，参数用 URLSearchParams 构造；响应按路由类型验证查询/分页/详情结构，不能因 query string 跳过校验。
6. offset、campus_id、详情 ID 增加明确整数上界，非法/溢出参数返回 422；不存在的合法 ID 返回 404，避免 SQLite 整数溢出变 500。
7. 查询状态分 draft、applied、已展示快照、page、dataset、requestId；表单从 draft 恢复，后台摘要/来源响应不重置学校选择。
8. 搜索/清空提交新查询并归第一页；翻页/重试只读 applied，保留其学校/校区/关键词/日期；学校变化清掉不适用校区，默认未知校区仍单独可达。
9. 默认电气含 related+unknown；全部招聘只放开 relevance，四种日期视图保持其它已提交条件；迟到响应被 AbortController/requestId 淘汰。
10. 保留旧结果时保留旧 applied/dataset/范围说明；不能挂新学校标题，也不能仅比较 ready 子集就认定全部已展示数据一致。
11. 分页携带首批 dataset；dataset_changed 的 409 丢弃旧分页，按当前已提交条件取第一页，绝不拼接新旧数据。
12. 修复跨北京时间午夜窗口移动但 dataset 不变的漏项：首请求返回查询日期/实际窗口，后续页复用。若选择过期重载方案，约定 `query_window_changed` 的 409；客户端同样清除旧分页，保留 applied 条件重载第一页，不能继续追加旧页。不把时钟变化伪装成业务 dataset 更新。
13. 缺发布日期的近期排序保留完整 first_seen_at 时刻，并用 ID 作稳定次序；不能截取日期后让同日记录随机/倒序。
14. 单独表达空库、该校暂未收录、无匹配、无未知日期项、请求失败。来源失败不替代已有列表，目录核验状态不由前端猜测。

关键反例：带筛选参数/单条详情确实发请求；未提交草稿后翻页；快速切校及迟到响应；同 dataset 跨午夜；409换代；超大数字；相关性/日期/未知校区；非法链接/HTML；长地址与多工作地。
完成证据：真实两校记录的列表→详情→原文/附件路径；带条件的 API/界面一致结果；数据换代与跨午夜分页材料；各页请求互不耦合。
关联：M1-01～08、A02～A04/A06/A07/A09/A10/A12。
