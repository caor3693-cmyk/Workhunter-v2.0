### AUD-01 / P1 / #22：固定上游响应不符合代理要求

已部署和当前版本的 `ops/preview/worker.mjs` 相同。其第 27—31 行先检查 HTTPS origin 格式、固定域名及服务令牌非空；第 37—42 行请求上游并拒绝重定向，随后仅在响应 `Content-Type` 不包含 `application/json` 时返回本次观察到的 `upstream_unavailable`。

因此，本次请求通过了配置的形式检查，并取得了不满足类型要求的上游响应。配置存在不证明 origin 仍指向正确实例，令牌非空也不证明令牌正确。类型不匹配还可能是缺失/错误 Content-Type 或其他 JSON 媒体类型，不能仅据此宣称响应正文必为 HTML。

正常 FastAPI 鉴权失败、数据库不可用分别会返回 JSON 401/503；本次六条请求的结果更应沿上游响应/通道定位。临时隧道错误页、错误 origin、API 未捕获 500 等仍须读取原始状态与脱敏现场日志区分。不能把 12:59 的观察倒推成原截图时点的完整根因。

**修复要求：**先在隔离开发宿主核对进程、端口、带服务鉴权的 health/version，再核对当前 HTTPS 通道、Site 配置和六条同源请求。代理保留有界诊断：请求标识、路径、上游 HTTP 状态、Content-Type、失败层；不记录令牌、内部 origin、完整响应。修复后在同一真实 Site 完成断连/恢复和身份回读，不用本机预览替代。

### AUD-04 / P1 / #23：锚点、构建和路由都没有独立页面支持

- `frontend/index.html:23–25` 为 `#main/#sources/#review`；`app.js:216,237` 仅展开 details。

### 4.3 M1 写链路必须补齐的约束

以下反例用一次性合成库直接写 SQL，证明基础约束缺口；当前还没有生产写服务，不能说这些错误已在真实采集发生。

1. `schema.sql:52–57` 的 `UNIQUE(source_key,opportunity_id,task_kind)` 不能阻止 opportunity_id=NULL 的重复列表任务；相同插入两次成功。#7 固定列表任务/栏目/窗口的幂等身份及断点。
2. `schema.sql:20–22` 的独立外键不保证学校、来源、校区属于同校；外键开启仍能形成华工记录关联广工来源/校区。#7/#8 在唯一写入口校验归属，必要迁移显式执行。
3. `queries.py:66–87` 只校验 JSON 最外层，可投影未知字段状态、对象型工作地和非法 URL。#8/#9 使用有限字段模型、七种状态、适用证据与安全链接校验；这不是已证明的前端 XSS，现有 `textContent`/安全 URL 校验应保留。
4. 已有库再次 init 不同步种子，`database.py:71–73,95–103` 也不能凭改 config 变成运行中已核验来源。#7 增加显式来源登记/配置同步。
5. dataset 只在初始化生成。#7/#8 的短事务要同时提交机会、证据、业务变化、断点、真实数据模式，以及公开投影变化对应的新 dataset；重复读取和仅巡检不能无故换代。详情失败保留可靠旧值和原观察时间。
