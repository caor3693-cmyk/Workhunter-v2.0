## 5. DOC 与 CORE 的共同完成条件

### 5.1 来源与字段

统一来源注册表应表达固定 school_key、source_key、栏目、官方入口/获准域名、第三方托管的学校租户关系、校区映射和能力状态。域名策略在各输入边界复用，保留安全 URL/重定向/响应体大小/类型校验；不能为了第三校去掉准入。

修复 #33：稳定任务和游标跨普通新轮次可继续推进；新头部发现与旧待补分配有限预算，失败退避和单校限制隔离；已完成且无新证据的详情不反复占先。至少验证三轮普通刷新、显式 resume、进程中断、重复分页、某校失败与预算终止。不得靠无限扫描或放大预算掩盖饥饿。固定3页、每页1条、每轮2列表页/1详情预算，连续3个普通新轮次后，3条详情均至少处理一次；中途加入新头部公告，新发现与旧待补均须在约定有界轮次内推进。已完成详情按到期复核策略再次访问；列表不变而详情正文变化时，仍应在该周期内发现并正确记账，不能永久跳过 committed 任务。

修复 #34：相关性以本公告适用岗位/专业为依据，企业背景命中不足；场地/工作地分离；支持可核验的标签值和表格，解析失败与未披露分开。保留 unknown 可见和失败不覆盖可靠旧值原则。新增语义修订通道，以明确证据纠正已知旧误判，不能让旧 known 值永远不可改。

对真实旧记录先只读审计、生成修订预览，实际操作限定在本次独立候选库；每项记录旧/新值、原因、证据和回退方式。使用统一 writer 原子提交历史与 dataset；真实影响数量未核验前不填写“已修复 N 条”。

HTTP200 但无法识别列表只证明取得页面，不能登记列表成功。明确已验证完整空页、有限已解析范围、解析失败、访问限制和未检查；失败不刷新 last_success 或旧字段证据时间。有效“零变化”与未知数量分开。

### 5.2 材料适用关系

修复 #35：稳定材料实体与公告适用关联分离，关联携带明确源身份、关系种类、locator/scope 和证据。写入/查询都验证本公告适用，允许合法共享列表材料各自有定位。官方附件需要从适用公告取得的链接链；同域不同公告或同名企业不等于同一记录。

事务内拒绝错属/缺失关系，不能留下半条记录、错误 change_history 或 dataset 更新。反例包含 A 引 B、B 后到达、共享列表两公告、同名企业、附件历史变化、事务失败、重复入库和读取损坏。隔离可疑旧附加关系并生成维护任务，可靠核心字段仍应可读。

### 5.3 统一写入与实际 schema2 迁移

冻结自动观察、人工导入、字段更正和撤回共用的写上下文：actor、run_id 或 operation_id、材料适用、目标版本、变更类型、原因、幂等标识与事务结果。人工操作不伪造 worker run；原文观察与人工决策分开保存，不能各服务重写一套事实。

当前实际库是 schema2。先保留可恢复备份，在独立候选上显式执行 schema2→新版本迁移；同时按原合同处理仍支持的 schema1 路径。保留机会 ID、材料、历史、data_mode 和数据身份规则；不删除重建真实库、不发明材料适用关系。失败原子回退或从备份恢复，有针对性故障证据。服务导入、GET 和 health 不迁移/建表。

## 8. W04-A：受保护维护页、材料和撤回

### 8.1 会话与 Site 同源链路

保持 Site 平台登录后，业务维护者建立单独会话；普通业务访客只读。后端服务代理令牌不等于维护者身份，不能让任意持有 Site 访问权的人写入。

业务会话服务端可撤销，浏览器 Cookie 使用 Secure/HttpOnly/SameSite；所有写接口验证会话、CSRF 与 Origin。代理仅放行登记的路由/方法/必要头，转发业务 Cookie，不转发 Site 平台 Cookie；Set-Cookie 的 Domain/Path 适配 Site。同一原点端到端测试，秘密不进入 JS bundle、仓库或 URL。

验证未登录、退出后、无 CSRF、跨 Origin、过期会话、非法路由/方法，读取受保护操作资料与写入均拒绝。保持 Site 平台登录但退出业务会话才是用户可执行的普通业务访客测试；Site 外层登录墙不是后端鉴权证据。

### 8.2 预览、保存与冲突

流程为输入官方链接/合法公开正文或附件→确认学校/公告适用→预览→明确保存→回执/历史。获取失败只记录待补，不凭 URL 编造内容。请求/文件大小、类型、重定向和来源边界受控，不提供任意 URL、文件路径、SQL 或命令接口。

预览绑定服务端会话、目标、操作类型、规范化输入、base_version、输入 hash 和到期时间。预览不写访客业务事实；正式保存重新验证绑定/适用并在统一 writer 原子提交。

相同幂等请求已成功提交后，即使原预览随后过期，仍返回同一已提交回执，不重复写入。未提交且过期、跨会话、换输入、换目标或 base_version 变化必须拒绝并要求重新预览，冲突使用明确 409。响应丢失后重试、双击和并发更新均测试。

自动新观察与人工更正并存，人工决策有字段级版本和原因；自动观察不能静默覆盖人工更正，发生真实冲突生成待核对任务。字段未冲突的可靠自动更新仍可按合同入库。

### 8.3 撤回

撤回撤销指定人工操作的贡献，保留原操作和撤回记录。字段更正撤回恢复当前仍适用的先前值，不覆盖后续合法变化；版本冲突先重新预览。

人工新增记录撤回时，若无其他有效事实来源，则撤销其人工可见贡献；仍保留材料和审计，不解释为官方取消，不删除别人后来取得的可靠事实。验证“更正→自动更新→撤回”“导入→重复导入→撤回”“后续另一人工更正”等组合。

## 9. W04-B：真实摘要与维护待办

摘要从真实提交的机会/字段/操作事件推导：当前新收录、历史补齐、日期待核实、官方业务变化、解析改进、人工更正/撤回分别计账；重复观察、重复保存和无变化重试不增加机会数。

同条机会多字段变化按约定的去重机会集合统计，并明确分类可否重叠，不能把字段条数冒称招聘数。按 Asia/Shanghai 的**实际提交日**归档业务变化，不把跨午夜完成的 run 全算到开始日。

当天没有采集 run 但有人工更正，应显示真实人工更正，同时来源显示未检查；无法确定的数量保持未知。HTTP200 解析失败不更新最近成功；“已检查无变化”“部分取得”“受限/失败”“未检查”分开。

维护待办按来源/原因聚合，提供公开限制、字段待补、材料隔离、人工/自动冲突及重试线索。技术原因留在受保护维护资料，访客摘要简明。M3 自然调度尚未启用时，不编造下一次运行时间或连续运营天数。
