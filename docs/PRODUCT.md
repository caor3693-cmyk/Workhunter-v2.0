## 1. 一句话定位

面向电气、自动化相关应届求职者，持续汇集十所学校的官方招聘公告与活动，让用户找到近期机会、看清时间地点和工作地，并进入官方原文继续了解或申请。

首版完成以下流程：

1. 选择学校及需要的校区。
2. 查看近期公告、临近活动或历史记录。
3. 阅读卡片中的时间、举办地点、工作地点。
4. 点击标题查看简要详情，或直接打开官方原文。
5. 查看真实更新摘要，了解信息是否得到持续检查。

学校转发招聘公告不代表企业线下到校，也不代表只允许该校学生投递。
不限制单一毕业年份；届次未披露、暂无岗位文本或企业名单，不阻止基础公告收录。

## 5. 页面与最小卡片

首版页面由招聘发现首页、公告简要详情、来源状态入口和受保护维护页组成。
首页顺序为学校/校区与搜索筛选、招聘卡片、分页或加载更多；按用户 #42 的要求撤去首页“最近更新”区块。
F07 的真实更新摘要继续在来源状态和维护入口提供，首页不再订阅摘要。其余骨架保持；普通来源修复不重排主页或更换全局样式。

| 区域 | 展示要求 |
| --- | --- |
| 识别头 | 使用准确原标题；一行学校与活动类型；标题可进入简要详情。 |
| 时间 | 活动显示举办日期及时段；普通公告显示发布时间；保留来源精度。 |
| 举办地点 | 使用本场会场；无活动安排时省略；明确线上才显示“线上”。 |
| 工作地点 | 使用本公告及其直接材料明确披露的实际招聘地点，与会场分行。 |
| 官方原文 | 一个指向准确官方目标的真实原文链接；缺失或不合法时如实说明。 |

卡片不添加名单、岗位列表、计数、解析状态、系统 ID、抓取时间、工资信息、额外按钮或折叠区。
多企业活动采用“已披露工作地点”，不暗示所有企业岗位都在这些地方。
多地点按来源精度自然换行，默认最多显示五项，超出注明“等，详见原文”。

列表已经包含日期、时段、校区或教室时，应直接提取和展示，不等待详情。
只有日期时不补 00:00；只有城市时不扩写详细地址。
原文中的总部、注册地址、公司名城市、学校所在地和会场，不能替代工作地点。

## 6. 简要详情的深度

简要详情集中呈现以下已取得内容：

- 与卡片一致的核心事实和官方来源。
- 本公告明确披露的取消、改期或招聘截止信息。
- 本公告已有的参会名单文本或可确认的名单条目。
- 本公告已有的岗位名称、专业、学历、届次等文本片段。
- 直接适用于本公告的官方附件及来源链接。

名单和岗位片段保留对应来源与适用范围；不同公告的同名企业不自动合并。
只取得部分内容时准确标为部分，不声称完整名单、全部岗位或全部工作地点。
附件打不开、详情受限或解析失败时保留已有事实和原文入口，不把失败说成原文未披露。
不要求完整复刻公告正文，也不启动全国企业抓取、独立岗位身份或完整名单分页工程。
后台仍可取得必要正文以补全时间、地点和工作地；这不扩大访客详情的产品范围。

## 7. 筛选、相关性与日期

筛选草稿与已应用查询分开；分页、加载更多和重试使用已应用查询。
切换学校清理不适用校区；迟到响应不能覆盖新查询，也不能把旧结果标作新学校结果。
“全部招聘”保留当前学校、校区、关键词和日期等条件，仅放开相关性范围。

相关性采用三个明确状态：

| 状态 | 默认电气列表 | 判定要求 |
| --- | --- | --- |
| 相关 | 显示，优先呈现 | 有本公告或其直接材料中的电气/自动化相关依据。 |
| 未知 | 保留 | 证据不足、详情未取得、活动范围广或尚未能确认。 |
| 已核实完全无关 | 不显示；全部招聘可见 | 已取得的适用材料足以确认完全无关，不能只凭标题缺词判定。 |

发布日期、举办时间、明确截止、系统首次收录和最近检查各有独立含义。
显示北京时间；日期型数据保持日期精度，不能通过时区转换造成跨日。
日期未知单独可达；不得用届次、收录时间或举办日补造发布日期。
默认近期范围采用近 30 天发布公告与未来 30 天已公布活动的并集，历史另可查看。
这是初始浏览与采集窗口，不是删除旧记录的条件。

关键字段区分已取得、尚未取得、待提取、解析失败、原文未披露、不适用与冲突。
访客只看到准确值或必要的“暂未取得”“待核实”“原文未披露”；技术原因在维护页。
活动结束不等于招聘截止；未见截止或取消不等于“已确认仍在招”。

## 8. 更新与采集核心

| ID | 支撑功能 | 必须成立的行为 |
| --- | --- | --- |
| D01 | 官方来源登记 | 学校、校区、栏目、归属与范围可追溯。 |
| D02 | 列表发现与持久化 | 按页及时提交有效记录，列表已有的时间地点直接落入字段。 |
| D03 | 按需详情补全 | 优先补核心字段，随后保存已经取得的简要内容；任务可续跑。 |
| D04 | 字段证据 | 核心字段能回到来源、片段/位置与取得时间，缺失原因明确。 |
| D05 | 去重与变更 | 同源记录幂等；改期更新原公告；不凭同名标题跨场合并。 |
| D06 | 定时与增量 | 无需打开网页或 Codex；预算有界、断点续跑、分源失败隔离。 |
| D07 | 官方材料补录与纠错 | 通过第 9 节维护页进入统一校验、去重、更正与撤回流程。 |
| D08 | 一致读取 | 页面、统计、API 与诊断可识别同一数据集及当前查询。 |

默认每 6 小时检查，健康可访问主来源不超过 24 小时未复核；48 小时明确标陈旧。
受限来源停止对应访问路径并明示原因，不绕登录、验证码或访问控制。
单源失败、预算耗尽和不完整分页不造成其他学校停工，不关闭旧公告或清空可靠字段。
访客 GET 读取已入库数据，不触发外站抓取、写库或临时大模型调用。

更新摘要区分近期新收录、历史补齐、日期待核实、官方业务变更、解析补全和人工更正。
“今日收录”不等于“官方今日发布”；重复抓取不增加新增数量。
未检查、检查无变化、部分成功、失败、暂停分别表达；未知不能填零。
公开摘要保持简洁，完整运行和字段处理信息放在维护入口。

## 9. 受保护的简易维护页

维护者可以贴官方链接，或在链接不可读时补充合法取得的公开正文、表格与附件。
操作流程为输入材料 → 核对来源与学校/场次 → 预览 → 明确保存；不能凭 URL 猜正文。
支持纠正核心字段、保留原因和依据、查看改动记录，以及撤回本次人工操作。
人工内容与自动采集共用公告身份、去重和证据规则，不建立第二套业务库。
自动重新采集不能无记录地抹掉人工更正；有冲突时进入维护待办。

| ID | 必要运行能力 | 首版范围 |
| --- | --- | --- |
| O01 | 来源状态与待办 | 正常、陈旧、失败、受限、待补，最近尝试/成功及下一次计划。 |
| O02 | 发布与数据恢复 | 明确版本、独立新库、有效备份、可重复恢复和回滚步骤。 |
| O03 | 只读诊断 MCP | 查询版本、来源、实际数据与有限日志；响应有界，不获得生产写权限。 |

维护页仅供获授权维护者使用，访客不能写入；不建设学生账号或复杂多人运营系统。
保存材料需校验来源、链接与附件边界；不开放任意服务器文件、命令或无保护写接口。
普通待遇未披露不进入补齐队列；待办优先影响时间、地点、原文和持续更新的问题。

## 10. 后置能力与明确排除

**后置，不在本轮自动扩展：** F11 独立岗位库/搜索，F12 全国企业官网直采，完整参会名单采集与身份关联工程。
后置能力只有在另一次产品范围明确后才能新增实体、接口、采集任务和验收目标。
本公告已经取得的名单及岗位文本属于 F10，不以此名义启动上述后置工程。

**本产品当前排除：** 学生注册登录、收藏及其同步、订阅推送、个性化推荐、自动投递、支付、社区。
不恢复薪资/周期、双休、倒班、出差、严格/宽松和细分工作地点筛选。
官方材料自然包含的待遇文本可以保留；不建设待遇调查、补齐、比较或排序。
不读取个人微信，不承诺任意公众号全部历史，不默认引入付费服务或通用 AI 抽取平台。

## 11. 新旧资产与交付定义

新代码、新业务库和运行目录独立；旧代码、旧库、原文与历史任务只读留存。
旧学校/校区/来源种子须复核归属后复用，少量可靠原文可作回归样本。
不直接迁移旧推断、可疑岗位合并关系或整套旧运行逻辑；旧 PR 不自动合入新项目。
旧仓库只读归档不等于删除仓库，旧站服务切换不等于恢复或覆盖数据库。

交付以真实操作链为准：选学校 → 找近期机会 → 看准核心字段 → 详情/原文可达 → 持续更新。
先以华工、广工打通流程，再扩十校；这个顺序不减少十校目标。
受限校如实列出，可交付其余学校；不得将配置数量或库存总数说成十校全面覆盖。
工程实现、真实浏览器验收、生产上线、线上复验和运营观察分别记录。
独立官方分母未知就写未知；不以大量测试、人工填零或未来运行记录代替产品结果。

## 12. 分阶段使用与反馈

按负责人 2026-10-10 的补充要求，开发目标为一周，排期见 [ROADMAP.md](ROADMAP.md)。开发期先在私有 Site 使用，每个阶段都交付 [MANUAL_QA.md](MANUAL_QA.md) 定义的按序手工核验清单。
负责人按 G0—G4 逐项反馈；失败补建或更新 Issue，修复后仍按原编号复验。自动测试完成、PR 合并或日期到达都不能代替用户确认。
所有阶段及首版必需反馈完成后，才执行正式部署与既有站点切换。Site 验收版本、隔离开发 API、正式生产环境分别记录，不将演示或旧站数据计作新版本验收。
